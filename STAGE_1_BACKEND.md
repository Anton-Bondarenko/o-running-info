# Этап 1: Структура проекта, База данных и API

## Цель этапа
Создать базовую структуру директорий, настроить SQLite, реализовать CRUD-операции для спортсменов и их беговых объемов, покрыть код тестами.

## Структура проекта
Создай строго следующую структуру:
```text
running-tracker/
+-- app/
¦   +-- __init__.py
¦   +-- main.py          # Точка входа FastAPI и роуты
¦   +-- database.py      # Подключение к SQLite (файл data/tracker.db)
¦   +-- models.py        # SQLAlchemy модели
¦   +-- schemas.py       # Pydantic схемы
¦   L-- templates/       # HTML шаблоны (для Этапа 2)
+-- data/                # Папка для файла БД (добавить в .gitignore)
+-- tests/
¦   L-- test_api.py      # Тесты API и бизнес-логики
+-- requirements.txt
+-- Dockerfile
+-- docker-compose.yml
L-- CLAUDE.md
```

## Схема базы данных (`models.py`)
1. **Таблица `athletes` (Спортсмены):**
   - `id`: Integer, Primary Key
   - `full_name`: String, обязательное (ФИО или никнейм с поддержкой эмодзи UTF-8 и базовых HTML-тегов: `<b>`, `<i>`, `<u>`, `<s>`, `<mark>`, `<font>`, `<span>`)
   - `rank`: String, опционально (Разряд: I, II, III, 1ю, 2ю, 3ю, КМС, МС)
   - `rusada_status`: Boolean, по умолчанию False (Сертификат РУСАДА: Да/Нет)
   - `dispensary_date`: Date, опционально (Дата окончания справки из физкультурного диспансера)
   - `clinic_status`: String, по умолчанию "Не надо" (Меддопуск поликлиника: "Да", "Нет", "Не надо" или дата окончания)
   - `is_active`: Boolean, по умолчанию True

2. **Таблица `training` (Беговой объем):**
   - `id`: Integer, Primary Key
   - `athlete_id`: Integer, ForeignKey(`athletes.id`, ondelete="CASCADE")
   - `date`: Date, Дата тренировки
   - `distance_km`: Float, по умолчанию 0.0

## Бизнес-логика (Хелперы)
Напиши функцию расчета статуса справки диспансера (`dispensary_date`) относительно текущей даты:
- Если даты нет -> статус `"none"` (серый).
- Если дата меньше текущей или до нее осталось <= 14 дней -> статус `"expired"` (красный).
- Если до даты осталось > 14 дней -> статус `"valid"` (зеленый).

## Задачи для выполнения
1. Создай файл `requirements.txt` с пакетами: `fastapi`, `uvicorn`, `sqlalchemy`, `jinja2`, `python-multipart`, `pytest`, `httpx`, `bleach`.
2. Напиши функцию санитизации `sanitize_name(raw_name: str) -> str` с помощью `bleach.clean()`. Разреши только теги: `['b', 'i', 'u', 's', 'em', 'strong', 'mark', 'font', 'span', 'marquee']` и атрибуты: `{'font': ['color', 'face', 'size'], 'span': ['class']}`. Все остальные теги (особенно `<script>`, `<img>`, `<a>`, `<div>`) должны вырезаться.
3. Применяй `sanitize_name()` при каждом создании или обновлении имени спортсмена.
4. Реализуй `database.py`, `models.py`, `schemas.py`. Убедись, что папка `data/` создается автоматически при старте приложения, если ее нет.
5. Реализуй базовые JSON-эндпоинты в `main.py` для проверки логики:
   - `GET /api/athletes` — список спортсменов с вычисленными статусами справок и суммой километров за выбранный год.
   - `POST /api/athletes` — добавление спортсмена.
   - `PUT /api/athletes/{id}` — обновление данных спортсмена.
   - `POST /api/trainings` — добавление или обновление (upsert) беговой тренировки.
6. Напиши тесты в `tests/test_api.py`, проверяющие создание спортсмена, обновление его пробега за январь/февраль, подсчет годовой суммы и логику определения просроченной справки, при сохранении `"<b>Иван</b> <script>alert(1)</script> ?"` в базе должно сохраниться `"<b>Иван</b> alert(1) ?"`.. 
7. Запусти `pytest` и убедись, что все тесты проходят.
